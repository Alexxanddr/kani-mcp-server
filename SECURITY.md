# Security policy

## Reporting a vulnerability

Do not open a public issue for a vulnerability or exposed credential. Until the maintainer publishes a private reporting channel, use GitHub's private vulnerability reporting feature if it is enabled. If no private channel is available, withhold sensitive details and ask the maintainer to establish one.

Include the affected version, impact, minimal reproduction, and suggested mitigation. Never send a real WaniKani token.

## Supported versions

The project has not published a supported release. Security support and response timelines will be defined before the first public release.

For the technical threat model and credential guidance, see [docs/SECURITY.md](docs/SECURITY.md).
